# Overview: 分割氏名の自動マルチボックス対応

## 課題

OCR（PaddleOCR）の認識結果において、同一フィールド（氏名）が複数のテキストボックスに分割されるケースがある。

**実例（raw_data より）**:

```json
[
  {"text": "山田",   "box": [[67,126],[205,130],[203,198],[65,194]]},
  {"text": "太郎様", "box": [[255,126],[379,135],[374,209],[250,200]]}
]
```

| 項目 | Box1 (山田) | Box2 (太郎様) |
|---|---|---|
| X範囲 | 67–205 | 255–379 |
| Y範囲 | 126–198 | 126–209 |
| 中心間距離 | ~181px（20px 閾値を超過） | |

### 現状の問題

- `search_coordinates(ocr_entries, "山田太郎")` が失敗 → 単一OCRエントリに存在しないため
- `coord_results["name"] = None` → テンプレート学習（Forward方向）不能
- 近接検索の20px閾値では結合矩形の中心点から両方のboxを同時検出不可能

### 解決方針

**自動マルチボックス検出**（UI上のチェックボックス不要）:

- **Forward（修正→テンプレート学習）**: テキスト検索失敗時に、サブストリング関係にあるOCRエントリをライン検出＋水平近接で収集し、マルチボックスとして保存
- **Reverse（テンプレート→抽出）**: マルチボックスに対して各boxを近接検索し、テキストをX順に連結して抽出値に反映

### 影響ファイル

| ファイル | 変更種別 |
|---|---|
| `app/coord_search.py` | マルチボックス検索ユーティリティ追加 |
| `app/structural_parser.py` | Reverse方向のマルチボックス対応 |
| `app/services/ocr_coordinate_service.py` | Forward方向のサブストリングフォールバック追加 |
| `app/template_feedback.py` | マルチボックス形式の保存対応（型ヒントのみ） |

### 非変更

- `app/web/server.py` — UI変更不要
- `app/web/templates/detail.html` — UI変更不要
- DBスキーマ — `coords_corrections` はTEXT(JSON)のまま。コード上の型解釈で分岐
