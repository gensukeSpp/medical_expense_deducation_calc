# Issue #34: 抽出時における"キー要素"を追加する

## 目的

現在、テンプレートマッチングのキーは「クリニック名」のみである。OCRでクリニック名の文字欠け（例: "ABCクリニック" → "BCクリニック"）が発生すると、テンプレートが適用されず、抽出精度が低下する。

本Issueでは、テキスト類似度および座標レイアウトによるフォールバックマッチングを追加し、クリニック名のOCRが不完全でもテンプレートが適用されるようにする。

## 参照

- [Issue #34 本文](https://github.com/gensukeSpp/medical_expense_deducation_calc/issues/34)
- [要件定義書.md](../../要件定義書.md)
- `app/structural_parser.py` — `_apply_template_corrections()` テンプレート適用のエントリポイント
- `app/coord_search.py` — `difflib.SequenceMatcher` 文字列類似度検索（既存）、`search_by_proximity()` 近接検索（既存）
- `app/db.py` — `get_clinic_by_name()`（読み取り専用、作成しない）
- `app/normalization.py` — `normalize_text()` 文字列正規化

## スコープ

### 含むもの
- テキスト類似度によるクリニック名マッチング（`difflib.SequenceMatcher` + `normalize_text()`）
- 座標レイアウトによるテンプレートマッチング（全テンプレートの `coords_corrections` と現在のOCRエントリを比較）
- 3段階フォールバック（完全一致 → テキスト類似度 → 座標レイアウト）
- マッチ時の `extracted["clinic"]` 上書き（正しいクリニック名でDB保存されるようにする）
- 単体テスト・結合テスト

### 含まないもの（次回タスク）
- テンプレートマージ・統合（同一レイアウトのテンプレートが複数できた場合のマージ）
- テキスト類似度の機械学習的改善
- 座標レイアウトマッチングのパフォーマンス最適化（テンプレート数が増えた場合のインデックス等）

## 受入条件

1. クリニック名が完全一致する場合、従来通りテンプレートが適用されること（後方互換性）
2. クリニック名に文字欠けがある場合（例: "BCクリニック" → "ABCクリニック"）、テキスト類似度マッチングによりテンプレートが適用されること
3. クリニック名が全く異なる文字列だが、座標レイアウトが一致する場合、座標レイアウトマッチングによりテンプレートが適用されること
4. いずれのマッチングも失敗した場合、従来通り新規クリニックとして処理されること
5. マッチしたテンプレートのクリニック名で `extracted["clinic"]` が上書きされること
6. 既存テスト（`test_structural_parser.py`, `test_coord_search.py` 等）が全てパスすること

## 設計判断

| 項目 | 決定 | 理由 |
|------|------|------|
| マッチング方式 | 3段階フォールバック（完全一致 → テキスト類似度 → 座標レイアウト） | 最も確実な方法から試行し、緩やかにフォールバックする |
| テキスト類似度しきい値 | 0.6（`difflib.SequenceMatcher.ratio()`） | "BCクリニック" vs "ABCクリニック" で ~0.86 となるため、文字欠け2-3文字程度を許容する値 |
| 座標レイアウトマッチングしきい値 | 0.6（全フィールドの60%以上が近接マッチ） | 最低限のレイアウト一致を担保。誤検出防止のため過半数を要求 |
| 近接しきい値 | 50px（`DEFAULT_PROXIMITY_THRESHOLD` を流用） | 既存の相対座標化後の残差対応値。新たな調整不要 |
| マッチ時のclinic名上書き | `extracted["clinic"]` を正しい名前に変更 | 以降の `get_or_create_clinic()` が正しい既存クリニックを参照するため |
| DB関数 | 読み取り専用関数（`get_clinic_by_name`）を使用 | フォールバック時は新規クリニックを作成しない |
